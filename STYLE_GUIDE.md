# Newsletter House Style

This is the working style guide for The AI Builder Dispatch.

## Observed writing pattern

The strongest samples in the repositories are systems-first and implementation-heavy. The writing tends to:

- state the objective directly;
- define constraints before proposing solutions;
- use concrete architecture and file structures;
- prefer practical instructions over broad motivational language;
- separate phases, responsibilities, and interfaces;
- use short declarative sentences for important rules;
- explain why a design choice exists;
- treat simplicity and reuse as engineering constraints.

## Newsletter adaptation

For the newspaper, preserve that underlying voice but make it more readable and personal:

1. Start with the situation.
2. State the problem or observation.
3. Explain the system or decision.
4. Show what changed.
5. End with the next move or lesson.

## Avoid

- generic AI hype;
- fake certainty;
- excessive motivational language;
- long introductions before the useful point;
- pretending a prototype is a production system;
- turning every note into a polished success story.

## Founder Story rule

Founder Story pieces should sound like a record, not a biography written after the fact. Keep the chronology, constraints, decisions, failures, and changes visible.

## Editorial goal

The newspaper should feel like a technical founder's field journal that happens to have the structure of a serious publication.
